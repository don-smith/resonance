# Architecture

Resonance is a local, manifest-driven workspace. The CLI reads the current working directory as the authoritative repository root, offers `resonate install` when `.resonance/config.json` is absent, and starts a localhost HTTP server only after a configuration exists. Installation always writes Shell and interactively selects Home and Docs; the configured package entries are an authoritative allowlist. The server serves the Shell document and package assets, then dispatches package-owned API routes under `/api/<package-id>/...`. `resonate member init` bootstraps a self-contained member-package repository with an explicit manifest, local contract snapshot, and package-authoring skill; `resonate member package create` scaffolds packages inside that repository.

Packages are Resonance's general extensibility and implementation units. A workspace is a user-visible surface mounted and navigated by Shell. A package may provide a workspace, but not every package must be a workspace; Shell is a required infrastructure package, not a workspace. Current Home, Docs, and Backlog packages provide workspaces. External member packages may provide additional workspaces. This relationship is descriptive for now and does not add workspace metadata or a second configuration model.

## Package boundaries

- [**Shell**](../src/packages/shell/README.md) owns the fixed browser bootstrap, primary navigation, workspace mounts, activation rollback, and shared layout.
- [**Home**](../src/packages/home/README.md) reads the configured repository landing source and renders the Home workspace in the browser.
- [**Docs**](../src/packages/docs/README.md) discovers Markdown beneath `HostContext.repositoryRoot`, exposes the tree/document routes, renders the Docs workspace whenever Docs is activated, and navigates relative links between discovered documents.
- [**Architecture**](../src/packages/architecture/README.md) reads the committed `architecture/` model and projections, exposes bounded evidence and deterministic validation, and renders the architecture workspace when explicitly configured.

Packages contribute method-aware routes, assets, navigation metadata, and one browser module through the shared package contract. Team packages are selected by checked-in `.resonance/config.json`; member packages are selected by ignored `.resonance/member-config.json` and loaded from one external live checkout. Team packages load first and win contribution conflicts. The host validates contributions transactionally, keys routes by `METHOD pathname`, and keeps optional package failures isolated. Route handlers receive package-safe request/response capabilities: bounded JSON parsing, JSON responses, request-abort notifications, SSE streams, and one bounded package-scoped JSON state document. They do not receive Node HTTP objects or arbitrary filesystem access. The Architecture agent is a separate package-owned runtime exception: its Deep Agents backend mounts the viewed repository at a virtual root with listing, reading, glob, and grep operations; it may write or edit files in the configured architecture artifact root and Markdown documents, while implementation files, credentials, and `.git` remain protected. Shell execution, traversal, and symlink escapes are rejected. Package cleanup callbacks run in reverse registration order when the HTTP server closes; disposal is idempotent.

## Transport and safety boundaries

The shared HTTP layer bounds JSON request bodies and provides SSE framing. The server preserves `405` responses and lists registered methods in `Allow`. SSE handlers do not attempt a JSON response after headers are committed.

Filesystem access remains server-owned. Resonance remains localhost-only.

Resonance-owned telemetry is host infrastructure rather than a configured package. The host creates one process-level telemetry interface and passes it through `HostContext`; packages emit structured logs and spans without depending on an exporter. Each record carries the viewed repository's Git origin name (or directory name when no origin is available) as `repository`, and Langfuse also receives it as a resource attribute so one local instance can distinguish repositories. The telemetry interface also supports grouping related traces with `session(sessionId)`; the Langfuse adapter maps that exporter-neutral session identity to `langfuse.session.id`. Console telemetry is enabled by default, while Langfuse export is optional repository-local process configuration loaded from the viewed repository's gitignored `.resonance/.env`. Telemetry does not capture prompts, model output, or secrets by default, and exporter failures do not fail package requests.

Architecture artifacts are repository-authored LikeC4 `.c4` files under the top-level `architecture/` directory, with package-owned JSON metadata for rules, patterns, and decisions. LikeC4 parses and layouts the model; `@likec4/diagram` renders the browser views. The Architecture package treats implementation evidence as authoritative for what exists, authored assertions as authoritative for intended structure, and views as projections. Validation is deterministic and reports `pass`, `fail`, or `unknown`; it does not block startup. Its optional agent uses the configured local OpenAI/OpenRouter model through package-owned tools and a repository-wide filesystem backend that allows architecture-artifact and Markdown updates while excluding credential files and implementation writes.
