Resonance user guide

Conversations

Exchange encrypted, attributed Markdown in public workspace channels over an already reachable direct network.

Start in #general

A new conversation-ready workspace starts with an empty #general. Any current member can post or create another public channel. A channel's creator can rename or archive it; archive is terminal.

This release has no private channels, per-channel membership, direct messages, replies, threads, edits, deletes, attachments, or approval controls.

Attributed messages and local unread state

Each message shows its author's workspace display name. Unread counts and Mark read positions stay on this installation and are never synchronized as read receipts.

Synchronization labels

  • Current — no known local conversation duty remains.
  • Waiting to sync — durable work, an encryption epoch, a departure, or a usable authorized peer is still pending.
  • Offline — another member exists, but no valid direct address candidate is known.

Encrypted outbox bytes survive restart and sparse recovery avoids requiring a user retry.

Direct-network and history limits

Conversation records use authenticated direct Commonware connections. Iroh carries membership and bounded secret-free bootstrap controls only. This release adds no conversation relay, rendezvous, NAT traversal, hole punching, STUN, TURN, or UPnP.

Admission and removal are forward-only after canonical membership convergence. Members need a LAN, VPN, Tailscale network, or equivalent reachable route.

Private local data

Exact ciphertext archives, durable duties, recovery state, and unread positions stay in private workspace storage. Signing and conversation-recipient keys use separate custody. See Local workspace data for details.
